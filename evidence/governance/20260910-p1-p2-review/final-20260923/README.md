обоснование и реализацию **одной конечной абстрактной конфигурации**. Принятие

## Точная конфигурация

50 процессов: 20 core, 8 boundary и 22 observers. Одна агрегированная serving
BS, одно устройство/UAV, один link, target, controller и service session.
Реализованная интеграция сохраняет явные boundary assumptions, mailbox/coalescing
и недетерминизм. Успех сервиса из доставки ACK не следует.
Не моделируются масштабируемая сеть, явные пакеты или отдельная destination
cell для handover. APP Crit/Agg остаются placeholders без переходов.

`inputs.json` фиксирует SHA-256 модели, генератора, полного candidate query
set, выбранного query set и исходных документов. `parameters.json` содержит
весь набор исходных констант и интеграционных значений. Время — абстрактные
единицы без физической калибровки.

Поле `instance_vector` сохраняет исторический статус proposal исходного файла
для точного provenance. Актуальность реализации определяется проверяемым
commit и текущими metadata, включая queue/attempt overlays; историческая
метка не является новым решением о статусе. `explicit_packet_queues=0`
совместимо с абстрактной occupancy queue: пакетных объектов не добавлено.

Очередь #43/#44: K=4, L=1, M=2, H=4; service-before-arrival, optional service
только в COMM/JOINT. ACK не удаляет работу. K+1 — поглощающее свидетельство
переполнения, sticky overflow сохраняется.

Attempts #45/#46: максимум primary=1, rollback=1, total=2 на эпизод.
Счётчики насыщаются на 2/2/3 для сохранения нарушения; это не разрешённые
лимиты. Старт — фактический приём failure в A_REC, счёт — фактические send
requests, конец — локальный результат. Duplicate start не очищает нарушение.
Счётчики не управляют guards, invariants или synchronization.

## Контракт последующей проверки

`selected-queries.q` содержит 15 явно перечисленных обязательств и диагностик.
`query-disposition.json` даёт disposition каждому запросу текущего candidate
pack; сам generator и его pack этим ревью не меняются.

C01: глобальное отсутствие deadlock, отсутствие queue overflow и превышения
attempt limits. Отдельно проверяется отсутствие protocol error recorder.
C02 ограничен исправленным MAC send-to-ACK/timeout интервалом: elapsed safety
вместе с корректной записью начала и отсутствием reset активного интервала
даёт bounded completion на **time-divergent executions**. Это не безусловное
утверждение termination на Zeno executions. Leads-to сохраняется отдельной
диагностикой, включая возможный отрицательный результат.

Проверки достижимости нужны для невакуозности. Достижимость Idle сама по себе
не подтверждает успешный ACK: для этого нужен trace фактического matching
ACK-перехода WaitPHYAck -> Idle. Timeout отмечается отдельно. Witnesses начала,
primary/rollback/two attempts, непустой/полной очереди не заменяют safety.
Все запросы выполняются на точной полной композиции; результаты reduced
harness нельзя переносить на неё. Сбой, timeout или отсутствие witness
отражаются явно, а не считаются положительной проверкой.
