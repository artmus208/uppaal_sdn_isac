## Object and instance vectors

Grow UAV contexts attached to one abstract serving BS. Each UAV has one link,
one target, one service session, a MAC queue and an SDN control context. This
is a finite network workload model, without packet-level or radio-interference
coupling. The shared resource is *queue service*, not an ACK, physical spectrum
allocation or the processing capacity of a centralized SDN controller.

| Component | N=1 | N=2 | Role |
|---|---:|---:|---|
| UAV / link / target / service | 1 each | 2 each | Per-entity production context |
| MAC contexts / SDN control contexts | 1 each | 2 each | Per-entity decisions, no global policy optimization |
| Shared abstract BS queue server | 1 | 1 | Active load environment and service arbiter |
| Core automata | 20 | 40 | All frozen PHY/MAC/SDN/APP templates, including placeholders |
| Private boundary automata | 7 | 14 | Frozen input/fault/service environments and bridges |
| Shared boundary automata | 1 | 1 | `SharedLoad` replaces every `Boundary_E_MAC_LOAD` |
| Observers | 22 | 44 | Frozen observer semantics, including known limitations |
| Total automata | 50 | 99 | `49*N+1` |

Executable bindings and exact process order: `generated/n*/instance-vector.json`.
The SDN count is N *logical control agents*. Calling this N independent physical
controllers or one centralized controller with bounded throughput is unsupported.
One shared controller with multiplexed telemetry, admission and ACK routing is a
larger redesign; it is unnecessary for a first shared-service scaling candidate.
This interpretation must be accepted before P4; increasing N beyond 2 is rejected
by this candidate generator until the family domain is reviewed.

## State, clocks and routing

Indexing is compile-time specialization: `u0_mac_queue_q`, `u1_mac_queue_q`, etc.,
not runtime arrays. Every global symbol, function, type, constant, process and
location ID from the frozen composition receives its entity prefix. Function
bodies and calls are renamed together. Local clocks (`x`, `p`, `m`, etc.) belong
to their private template instance; no local clock is shared across entities.
Original globals, including clocks and mailboxes, remain shared *within* one
entity's 49 retained processes, preserving original multiple-writer semantics.

All original binary and broadcast channels are private to one entity. Reports,
command/ACK kinds, payload staging, source age, loss, coalescing and observer
order retain the frozen implementation. There is no cross-UAV admission outcome,
ACK or KPI broadcast. The only cross-entity functional reader/writer is SharedLoad.
It reads every queue and schedule mode, and writes each entity's MAC load/queue
inputs and sample-age/validity fields. Other state remains untouched. The complete
endpoint inventory is generated by `check.py`, including dormant source channels.

SharedLoad publishes `u{i}_bus_new_mac_sample!` to that entity's frozen B_KPI
receiver, then offers binary `u{i}_mac_mac_tick!` to its MAC scheduler. The latter
can be dropped with its own `u{i}_bus_tick_missed=true`, as in the baseline.
No unindexed common broadcast or ambiguous binary receiver is introduced.

## Shared arbitration and queue step

Every 5 abstract time units, a committed chain stages the seven finite input
choices for each UAV in private bounded scratch fields. Staging has no functional
side effects and time cannot pass. It avoids compiling the full Cartesian product
of both UAV input vectors in one select clause. Then one atomic transition samples a single
`server in {-1, 0, ..., N-1}`. `-1` permits no service. Selecting i is enabled
only if its *old* queue is nonempty and its mode is COMM or JOINT. Choices are
nondeterministic: no work conservation, round-robin, priority or fairness is
assumed. Each entity independently selects arrival in {0,1} and its six frozen
MAC load classes. All updates use service-before-arrival:

```
s_i = 1 if server == i else 0
q_i' = q_i                         if q_i > K
       q_i - s_i + arrival_i      otherwise
K=4; overflow_i' = overflow_i or (q_i' > K)
```

The absorbing value 5 preserves an overflow witness; choosing that queue can
consume a service slot without clearing the witness, just as in the frozen
abstraction. This is not a physical post-overflow queue. ACK never removes work.
Queue classes are derived after occupancy update with frozen L=1, M=2, H=4.
Other input domains and mappings are retained exactly. Passive `family_grant_i`
and `family_last_server` record the last selected service opportunity, *not*
successful SLA, application progress or useful departure after overflow.

One epoch can choose only one i. For old queues (1,1), both modes COMM and no
arrivals, possible next queues are (1,1), (0,1), (1,0); (0,0) is excluded. Two
independent copies allow (0,0). This is concrete shared-capacity interaction;
changing one entity's service allocation affects what is available to the other.
Subsequent queue classes feed its MAC/SDN/APP path through existing bridges.

After sampling, committed Publish/Offer states deliver notifications in increasing
UAV index. Time cannot pass in that finite chain, but other committed automata
may interleave under UPPAAL semantics. There is a skip for each binary tick;
SharedLoad cannot wait for an unavailable receiver. It does not establish global
deadlock freedom or time divergence. Within each private context, original
broadcast receiver order is preserved; SharedLoad replaces the first old load
process at its original system position. This fixed notification order may matter
for global interleavings and is part of the candidate semantics.

## N=1 correspondence and explicit differences

The frozen XML SHA-256 is
`592678ed678ce8f70cf278f542e48bd2bb739969b53a962423d3e63f91e3e1e2`.

1. All 49 retained templates and their declarations/edges/guards/invariants are
   structurally identical after removing the `u0_` identifier prefix. All global
   declarations/functions are the same renamed text. Local clock scopes are unchanged.
2. The old load template's three states and four edges become four states and
   five edges for N=1: an extra committed input-staging step precedes the original
   atomic queue update. Its local scratch fields are not visible to other components. The bijection is `service=0 <-> server=-1`,
   `service=1 <-> server=0`. The new eligibility guard has the same truth table
   over old occupancy 0..5 and all five schedule modes. At the final service
   transition, staged arrivals/classes and ordered updates match under this
   substitution. The new staging can interleave with other committed processes;
   local macrostep correspondence does not prove whole-composition equivalence.
3. SharedLoad has passive grant/last-server recording and local input scratch fields. No functional edge reads
   it; future queries can observe it. Template/process/location names and XML
   serialization change. Selected queries are explicitly external and renamed;
   shared-resource diagnostics are additional queries.
4. For N=2, common service selection replaces independent load ticks, all queue
   updates are atomic in one epoch, and notifications are serialized at zero time.
   This is a semantic change requiring acceptance and a new Gate 1.

`check.py` checks items 1–3 structurally and evaluates queue-step/guard cases.
This supports correspondence of the edited local step; it is **not** a reviewed
whole-system timed-bisimulation proof, property transfer argument or cutoff.
Old P3 results retain their original scope and are not assigned to these XML.

## Preserved assumptions and open decisions (v2 §1.1)

Frozen abstract units, finite classes (possibly physically inconsistent samples),
per-entity one-session/one-fault envelope, typed ACKs, timing bounds, optional
service, loss paths, APP placeholders and historical observer shortcomings remain.
In particular D_meas=5 versus T_meas+J=6 and deferred admission recording are
not repaired here. N contexts also multiply possible fault events/targets.
No empirical calibration, interference model, fairness, global deadlock, SLA
or controller-capacity claim is introduced.

| Open decision | Grounds / consequence | Return condition / recommendation |
|---|---|---|
| One shared service unit per tick | Minimal common bottleneck compatible with N=1 queue step; may under/overestimate actual capacity | Before P4 accept this abstract family, or specify another capacity/arbiter in a new candidate; keep optional service initially |
| Per-UAV SDN contexts vs shared controller | Avoids inventing unsafe cross-request ACK/admission correlation; omits controller contention | Revisit if P4's question is controller saturation; then design a separately reviewed multiplexed controller |
| Fairness / progress | Frozen service already optional; starvation remains possible | Add fairness only if required by the chosen property and with a new semantics decision |
| Whole-composition behavior | Only structural checks and bounded initial-state load are in this deliverable | Before resource series agree nonvacuity and behavior checks; no long run needed to finish this prototype |
| Family domain / property scope | Only N=1,2 demonstrated; old evidence not transferred | P2/P4 accept domain, queries and provenance; P0 records new Gate 1 before resource measurements |

## Future property schema

`generated/n*/queries.json` carries null verdicts and explicit roles. Keep one
global deadlock query; instantiate the 14 remaining frozen obligations/diagnostics
per entity without changing their expression. Add shared-capacity safety and
per-entity service-choice / joint-backlog reachability. Initial-state `load.q`
is separate and is never used as a nonvacuity or scientific verification result.
Elapsed MAC ACK semantics still require time-divergent executions; unconditional
leads-to remains a diagnostic. Family fairness, service opportunity, ACK,
admission and SLA remain different claims. Query meanings, observer disposition,
search strategy, resource budgets and cross-baseline correspondence need approval
before P4. R03/R04/C06 and scientific gates stay open.
